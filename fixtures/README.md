# Fixtures

All data under this directory is **invented synthetic test data**, checked in
for reproducible tests and as explicitly-labeled mock data for the frontend.
Nothing here is a real observation of any machine.

## `snapshots/` — merged NetworkSnapshot documents (JSON)

Schema-locked from both sides: the Rust tests in
`crates/core/tests/fixtures_roundtrip.rs` parse every file with the
authoritative serde model, and the frontend unit tests parse the same files
with the TypeScript mirror of the model. A change to either side that breaks
these files fails the test suite — this is the manual type-sync contract
described in `docs/development.md`.

| File | Scenario | Covers |
|---|---|---|
| `workstation.json` | laptop with ethernet + wi-fi + wireguard + bridge + dummy | loopback, ethernet, wireless, vpn, bridge, dummy, multi-interface, IPv4/IPv6, multiple default routes, local table |
| `incomplete-observations.json` | netlink failed; only sysfs/procfs observed | provider failure, degradation, missing fields, classification caveats, implied route table |
| `server-tunnel.json` | server with tunnel default (no gateway) and ethernet default | on-link default (observed absence of a gateway), tunnel interface, server-style machine |
| `dummy-virtual.json` | bridge port, vlan parent, veth pair, dummy | structural relations the topology projection draws (bridge/vlan/veth), virtual interface kinds |
| `empty.json` | no observations at all | a valid observation of an empty environment (zero interfaces/addresses/routes) |

The five snapshot fixtures pair one-to-one with the topology goldens in
`topology/` (same names); the frontend's scenario registry
(`apps/frontend/src/lib/scenarios.ts`) describes them for presentation with
explicit synthetic provenance.

## `sysfs/` and `procfs/` — synthetic kernel filesystem trees

- `sysfs/<scenario>/` is an injectable **sys root** (expects
  `<scenario>/class/net/...`).
- `procfs/<scenario>/` is an injectable **proc root** (expects
  `<scenario>/net/route`, `<scenario>/net/if_inet6`).

Generated by `scripts/gen-sysfs-fixtures.sh` (ported from the surviving WO-01
fixture script, extended during reconstruction); the generated trees are
committed so tests do not depend on the generator having run.

| Scenario | Contents |
|---|---|
| `sysfs/basic-workstation` | lo, eth0, wlan0 (original WO-01 data) |
| `sysfs/virtual-interfaces` | lo, br0 (bridge), wg0 (ARPHRD_NONE), dummy0 (original WO-01 data) |
| `sysfs/combined-laptop` | lo, eth0, wlan0 with ifindexes matching the procfs counterpart |
| `sysfs/empty` | no interfaces |
| `procfs/router-ish` | main-table routes + if_inet6 (original WO-01 data) |
| `procfs/combined-laptop` | routes + if_inet6 consistent with `sysfs/combined-laptop` |
| `procfs/empty` | header-only route file, empty if_inet6 |
