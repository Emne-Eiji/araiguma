# Fixtures

All data under this directory is **invented synthetic test data**, checked in
for reproducible tests and as explicitly-labeled mock data for the frontend.
Nothing here is a real observation of any machine.

## `snapshots/` — merged NetworkSnapshot documents (JSON)

Schema-locked from both sides: the Rust tests in
`crates/core/tests/fixtures_roundtrip.rs` parse every file with the
authoritative serde model, and the frontend unit tests parse the same files
with the TypeScript mirror of the model. A change to either side that breaks
these files fails the test suite — this is the manual type-sync contract
described in `docs/development.md`.

| File | Scenario | Covers |
|---|---|---|
| `workstation.json` | laptop with ethernet + wi-fi + wireguard + bridge + dummy | loopback, ethernet, wireless, vpn, bridge, dummy, multi-interface, IPv4/IPv6, multiple default routes, local table |
| `incomplete-observations.json` | netlink failed; only sysfs/procfs observed | provider failure, degradation, missing fields, classification caveats, implied route table |

## `sysfs/` — synthetic sysfs/procfs trees

Directory trees shaped like `/sys/class/net` and `/proc/net` for the sysfs
provider's injectable-root tests. Generated by
`scripts/gen-sysfs-fixtures.sh` (ported from the surviving WO-01 fixture
script); the generated trees are committed so tests do not depend on the
generator having run.
